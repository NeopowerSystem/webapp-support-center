# WebApp 智能客服中心｜前端套件實作規格

**狀態**：第一版開發規格。  
**依據**：使用者提供的手機 UI 與《FE前端智能客服文檔.docx》。  
**整合環境**：`webAppSmarthub` 使用 React 19、Vite 與 React Router。  
**客服信箱**：`neopowertechinfo@gmail.com`。

## 1. 第一版交付範圍

- 交付可由 npm 安裝的 React UI 套件，內建繁體中文固定 FAQ、6 個分類、16 題及 5 個熱門入口。
- 採手機優先設計，支援 iOS／Android 瀏覽器與 App WebView，並提供平板及桌面配置。
- 支援首頁、分類列表、解答、已解決、聯絡表單及郵件預覽。使用者自行從郵件程式送出。
- 套件可獨立展示 FAQ 與 Email 回報。SmartHUB 接入既有會員、站點及交易頁後，可提供對應操作與授權後的交易資料。
- 第一版以靜態問答及 Email 為客服流程。即時真人對話、生成式 AI、客服工單、後端寄信及 CPO／車隊合作列為範圍外。

## 2. 畫面與響應式規格

### 首頁

1. 選用宿主頂欄。SmartHUB WebView 已有「SmartHub WebApp」和關閉按鈕時，由宿主顯示。獨立頁面可由宿主提供同等導覽。
2. 顯示「智能客服中心」及「您好，請選擇您遇到的問題，我們會提供處理方式。若仍無法解決，可整理問題資料並透過 Email 聯絡我們。」
3. 灰底提示「此頁提供自助指引，非即時真人對話。」
4. 依下表顯示五個熱門入口，標題可使用圖稿短文案，解答由同一個問題 ID 取得。

| 熱門入口 | 問題 ID |
| --- | --- |
| 插槍後無法開始充電 | `charge.start_failed` |
| 無法停止充電／拔不下充電槍 | `charge.stop_failed`，解答另提供連結至 `charge.connector_locked` |
| 已付款，但畫面仍顯示未完成 | `payment.paid_pending` |
| 充電失敗卻扣款／疑似重複扣款 | `payment.duplicate_or_refund` |
| 發票、收據與交易紀錄在哪裡查看？ | `invoice.missing` |

5. 分類順序為充電問題、付款與費用、發票與載具、站點查詢、登入問題、其他問題。卡片包含線條圖示、標題、摘要和箭頭。
6. 底部顯示「找不到您的問題？聯絡客服」，直接進入聯絡表單，預選「其他問題／找不到我的問題」。

| 可用內容寬度 | 版面 |
| --- | --- |
| 小於 360 px | 分類單欄，熱門問題單欄，表單操作可堆疊。 |
| 360–767 px | 分類雙欄、熱門問題單欄，保留手機圖稿的區塊順序。 |
| 768–1023 px | 內容置中，分類三欄，熱門問題保持單欄。 |
| 1024 px 以上 | 首頁內容最寬 1120 px。說明跨欄，熱門問題與分類左右並排，右側分類雙欄，聯絡入口跨欄。解答、表單與預覽使用最寬 720 px 的置中內容欄。 |

若套件嵌在桌面側欄，依元件容器寬度排版。使用白底、黑字、灰色提示、細框圓角卡片、黑底主要按鈕。互動目標至少 44 × 44 CSS px，文字可換行，320 px 寬下無水平捲動。保留明顯鍵盤焦點及表單錯誤文字。裝飾圖示對輔助技術隱藏。換頁後將焦點移至新頁標題，返回時恢復清單焦點。WebView 預留安全區，鍵盤開啟時表單及操作仍可捲動。

## 3. 問題樹與導覽

分類 ID 使用 `charging`、`payment`、`invoice`、`station`、`account`、`other`。依文末 FAQ 建立 TypeScript 靜態資料，每題定義 `id`、`categoryId`、`title`、`answer`、`actions` 及選用的 `relatedQuestionIds`。問題 ID 穩定，標題和文案可調整。熱門入口與分類共享同一題設定。

- 首頁 → 分類 → 問題 → 解答。熱門入口及外部錯誤頁可以直接進入解答。無效的分類或問題 ID 回到首頁。
- 解答提供「已解決」、「仍未解決」、「聯絡客服」及返回。從分類進入時返回分類，其他入口回到客服首頁。每題均有聯絡客服入口。
- 已解決頁顯示「很高興能協助您，祝您使用順利。」可回到有效的來源頁或客服首頁。返回目的地由宿主路由決定。
- 仍未解決或聯絡客服會帶入目前分類、題目與允許的上下文。表單與預覽往返時保留已輸入資料。
- 一般 FAQ 和 Email 回報可匿名使用。需要個人交易資料時由宿主處理登入，登入成功後恢復原問題與上下文。取消登入或授權失敗時仍可手動填表。

## 4. 聯絡客服與手機號碼

| 欄位 | 規則 |
| --- | --- |
| 問題類別、問題選項 | 必填，可修改。切換分類時清除原分類的選項，讓使用者重新選擇。 |
| 問題說明 | 必填，去除首尾空白後至少一字。 |
| 聯絡手機 | 選填，使用 `type="tel"`，允許含國碼的輸入，保留前導 0 及 +，由使用者自己填寫。提供「如希望客服回電，可留下手機號碼」提示。 |
| 發生時間 | 選填。已確認的交易時間轉為台灣時間，畫面與郵件均標示時區。 |
| 場站、槍號、Session 編號、交易編號、顯示金額／付款時間 | 選填。可由宿主帶入已授權且確認的資料，也可由使用者補充。 |
| 錯誤碼／reqId、已嘗試的處理方式 | 選填。只帶入當次操作必要資訊。 |

表單通過驗證後進入郵件預覽。預覽顯示收件人、主旨及完整內文，提供「複製客服信箱」、「複製問題內容」、「開啟郵件程式」與「返回修改」。手機號碼隨預覽顯示，留空時標記「未提供」。若營運方提供正式客服電話，可透過宿主設定顯示號碼及 `tel:` 撥號入口。預設只有 Email，因原稿未提供客服電話。

**主旨格式**　`[EMSP 問題回報] {問題類別}－{問題選項}`

```text
客服您好：

問題類別：
問題選項：
問題說明：
聯絡手機：
發生時間（台灣時間）：
場站名稱：
槍號：
Session 編號：
交易編號：
顯示金額／付款時間：
錯誤碼／reqId：
已嘗試的處理方式：

如需截圖，我會自行附在此封郵件中。
```

- 各空白欄位顯示「未提供」。預覽可提醒使用者在郵件程式手動附上截圖。
- 點擊開啟郵件程式時才組裝 `mailto:`，主旨與內文分開編碼。提示「已嘗試開啟郵件程式，請確認內容並自行寄出。」 若宿主能回報啟動失敗，提示複製備援。寄送及收件由郵件程式和客服信箱處理。
- WebView 可由宿主原生層處理 `mailto:`。複製入口與可手動選取的文字始終可用，涵蓋未安裝郵件程式、剪貼簿受限及郵件連結過長等情境。
- 表單草稿保留在目前操作流程的記憶體。手機號碼、Token、密碼、驗證碼及付款敏感資料不得放入客服路由、持久化儲存或分析事件。Email 僅包含允許的預覽欄位，並提示勿輸入完整卡號、安全碼、密碼或驗證碼。自由文字以純文字渲染。

## 5. npm 套件介面

建議套件名稱 `webapp-support-center`，供本機與 tarball 使用。發布至 GitHub Packages 時，名稱使用 `@<GitHub 擁有者>/webapp-support-center`，安裝與匯入路徑需加上該 scope。以下介面是實作契約。

```sh
npm i ./webapp-support-center-0.1.0.tgz
```

```tsx
import { SupportCenter } from 'webapp-support-center';
import 'webapp-support-center/styles.css';

export function SupportPage() {
  return <SupportCenter />;
}
```

| API | 用途 |
| --- | --- |
| `initialQuestionId?` | 從宿主錯誤頁直接開啟指定問題。 |
| `context?` | 接收必要的上下文識別碼，如 `sessionId`、`cdrId`、`locationId`、`errorCode`、`reqId`。 |
| `supportEmail?`、`supportPhone?` | 客服 Email 預設使用本規格信箱。客服電話為選用。 |
| `actions?` | 以固定 action ID 提供宿主操作函式，如 `viewOutstanding`、`backToCharging`、`refreshPaymentResult`。未配置的宿主操作隱藏。 |
| `loadReportContext?` | 按需讀取經授權的回報欄位。宿主負責登入、會員 API 和權限判定。 |
| `onReturnToSource?`、`openEmailDraft?` | 宿主提供來源頁返回與 WebView 開啟郵件草稿的選用方式。 |

- 建議以 Vite library mode 產出 ESM、TypeScript 型別宣告及獨立 CSS。公開匯出 React 元件與其型別，透過 `exports` 開放根入口和 `./styles.css`。
- React 與 React DOM 使用 peer dependencies 並排除於打包，第一版驗證 React 19。CSS 以元件根節點限定範圍，使用者端無須安裝 Tailwind 或指定 Router。
- 套件包內包含建置輸出與最小整合 README。發行前執行 `npm pack --dry-run` 檢查收錄檔案，再用 `npm pack` 的 tarball 在乾淨 React 19 專案執行安裝、匯入樣式、開發預覽及 production build。通過後發佈到團隊選定的 registry。

## 6. 宿主串接範例（SmartHUB）

| 場景 | 沿用既有頁面/API（相對於 /api/v1） |
| --- | --- |
| 掃碼／場站 | 掃碼頁及 `POST /charging/resolve-qr`；`GET /stations/:stationId` 使用公開列表的 OCPI locationId。 |
| 充電啟動、進行中、停止中 | 返回充電頁，沿用 `GET /charging/sessions/:sessionId/stream`。 |
| 未付款或待結算 | `GET /charging/outstanding`，區分未付款及等待 CDR。 |
| 結算／手動更新付款 | `GET /charging/sessions/:sessionId/settlement`。手動更新或付款平台返回時單次加上 `refreshPayment=true`，一般輪詢使用基本路徑。 |
| 重新付款 | `FAILED` 且符合宿主條件時引導至原結算頁，原頁確認後使用 `POST /charging/sessions/:sessionId/settlement/retry`。 |
| 訂單、發票與付款紀錄 | `GET /billing/orders`、`GET /billing/orders/:cdrId`、`GET /billing/orders/:cdrId/payments`。 |
| 載具設定 | 前往原載具設定頁，由原頁使用 `PUT /billing/mobile-barcode-carrier`。 |

結算狀態沿用宿主契約。

| 狀態 | 行為 |
| --- | --- |
| `NOT_STARTED` | 顯示尚未開始結算或資料處理中。 |
| `PROCESSING` | 顯示處理中。 |
| `PAYMENT_REQUIRED` | 由宿主依 `payment.nextAction` 引導。 |
| `FAILED` | 導回符合條件的既有重付操作。 |
| `SETTLED` | 顯示已結算並關閉同筆交易付款入口。 |

- 宿主使用既有會員身分查詢授權資料，確認後才可帶入交易與郵件欄位。網址參數僅當作查詢線索。查無交易、無權限或網路錯誤時保留固定 FAQ 和手動回報。需更新狀態時提示「暫時無法取得最新狀態，請稍後再試。」
- 套件內的營運操作以導覽或查詢為主。充電控制、付款、退款、取消預授權、開立發票及修改載具由宿主的既有操作與確認流程處理。
- 正式接入前用實際路由及 API 回應核對操作映射。付款平台返回、停止充電及發票狀態皆需由各自的服務結果判定。

## 附錄｜16 題固定 FAQ 與操作文案

以下沿用原 Word 文件第 4 節，作為第一版預設問答內容。
### 4.1 充電問題

#### 4.1.1 charge.start_failed

問題：插槍後無法開始充電

請先確認現場安全，再依序檢查：

確認 App 已登入，並核對場站、充電樁及槍號是否正確。

確認充電接頭與車輛相容，且充電槍已確實插妥。

檢查車輛是否設定充電排程、已達電池充電上限（SOC），或存在其他充電限制。

確認會員付款方式及充電授權是否有效。

若 App 顯示尚有未完成付款，請先查看相關付款紀錄。

若顯示上一筆充電仍在結算，請先查看其處理進度。

若設備允許，可依現場操作指示結束原請求，再重新嘗試一次。

若仍無法啟動，請保留場站名稱、槍號、錯誤碼、發生時間及錯誤畫面，方便後續與站端營運商確認。

操作按鈕：

查看未完成交易

返回充電頁

聯絡客服

#### 4.1.2 charge.qr_failed

問題：掃碼後找不到充電樁

請確認掃描的是該充電設備提供的充電 QR Code，而非其他識別碼。

請重新掃描，並核對場站名稱、設備編號與槍號。

若仍查無設備，可返回場站地圖，查看場站及充電設備資訊。

請保留 QR Code 所在設備的槍號及錯誤畫面，以便後續確認。

操作按鈕：

重新掃碼

查看場站

聯絡客服

#### 4.1.3 charge.starting

問題：一直顯示啟動中

充電啟動指令送出後，仍需等待設備回報。

請返回充電頁確認最新狀態。

畫面尚未確認開始前，不代表設備已正式開始充電。

若設備已開始供電，但 App 仍顯示啟動中，請保留發生時間、場站名稱及槍號，並聯絡客服。

操作按鈕：

返回充電頁

聯絡客服

#### 4.1.4 charge.stop_failed

問題：無法停止充電／一直顯示停止中

請先從原本啟動充電的 App 執行「停止充電」。

停止指令送出後，仍需等待設備確認。

畫面顯示「停止中」，不代表充電已結束。

若停止指令尚未完成，請勿直接拉扯充電槍。

請依現場設備標示的操作指引處理，並記錄發生時間及錯誤畫面。

若現場持續充電且無法正常結束，請優先聯絡充電站現場標示的客服或設備營運商。

操作按鈕：

返回充電頁

聯絡客服

#### 4.1.5 charge.connector_locked

問題：充電結束後無法拔下充電槍

請先確認 App 或車輛已顯示充電結束，再依序檢查：

確認設備已完成停止充電程序。

查看車輛是否仍啟用充電槍鎖定功能。

依車輛使用手冊，使用車輛解鎖或原廠指定方式解除充電槍鎖定。

若仍無法拔出，請聯絡現場設備營運商協助處理。

安全提醒：

請勿強行拉扯充電槍、拆卸設備或自行操作配電設施。

若發現冒煙、異味、火花或其他立即危險，請遠離現場，並依現場緊急指示尋求救援。

操作按鈕：

返回充電頁

聯絡客服

#### 4.1.6 charge.awaiting_bill

問題：充電結束後沒有明細或金額

充電結束後，需等待充電站營運商回傳最終交易紀錄，系統才能確認充電度數、金額及付款狀態。

請查看該筆交易的結算進度。

若目前仍顯示處理中，請稍後重新查看。

資料尚未完成結算時，畫面可能暫時沒有最終金額。

此狀態不代表付款失敗，也不代表可以重新發起付款。

操作按鈕：

查看結算進度

聯絡客服

### 4.2 付款與費用

#### 4.2.1 payment.failed

問題：付款失敗／尚有未付款紀錄

請先開啟該筆交易，確認目前的付款狀態。

若付款仍在處理中，請等待系統更新結果，避免重複操作。

若系統已確認付款失敗，且畫面提供重新付款選項，可依指示完成付款。

只有符合系統重新付款條件時，才會顯示重新付款按鈕。

操作按鈕：

查看交易

重新付款（符合條件時顯示）

#### 4.2.2 payment.paid_pending

問題：已付款，但畫面仍顯示未完成

付款平台與充電服務系統之間的交易結果同步，可能尚未完成。

請返回該筆交易，使用「更新付款結果」重新確認。

若付款平台已顯示成功，但充電服務畫面持續顯示未完成，請保留：

交易編號

付款時間

付款金額

付款成功畫面

請勿在尚未確認付款結果前重複付款。

操作按鈕：

更新付款結果

查看交易

聯絡客服

#### 4.2.3 payment.amount_question

問題：充電費率與金額有疑問

不同場站與會員平台可能採用不同的充電計費方式。

請先查看充電前顯示的適用費率，以及充電完成後的交易明細。

常見費用項目可能包含：

電度費： 依實際充電度數計算。

時間費： 依適用的計時規則計算。

佔位費： 依場站規定，在符合特定條件後可能收取。

停車費： 可能由停車場另外收取。

漫遊費率： 不同會員平台可能提供不同的收費標準。

實際金額請以充電前顯示的適用費率及交易明細為準。

若仍有疑問，請提供交易編號及您認為有差異的費用項目。

查看交易明細

#### 4.2.4 payment.duplicate_or_refund

問題：充電失敗卻扣款／疑似重複扣款／申請退款

請先核對付款紀錄，確認款項目前的狀態。

常見狀態包括：

預授權： 可能只是暫時保留信用卡額度，尚未完成實際請款。

付款處理中： 付款平台與系統的結果可能尚未同步完成。

已完成付款： 可核對交易時間、金額及交易編號。

若發現充電失敗卻產生費用，或疑似有兩筆相同扣款，請整理相關付款紀錄與原因，透過 Email 聯絡客服。

退款需要由管理人員確認交易與金流紀錄。

寄出問題回報不代表退款已核准或完成。

請勿提供完整信用卡號、信用卡安全碼、密碼或其他敏感付款資訊。
